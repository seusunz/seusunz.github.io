2026-11 更新：初版只写到“部署成功”，后半部分一直是空标题。本次按本站的实际做法重写，并补上“问题记录”一节，这部分比搭建步骤本身更有用。

1. 为什么选 Hexo + GitHub Pages

方案 优点 缺点
公共博客平台 零维护，搜索引擎收录好 排版受限、广告多，内容迁移难
自购服务器 + 域名 完全自由 成本与运维负担高
Hexo + GitHub Pages 免费托管、Markdown 写作、源文件完全自己掌握 需要一点命令行基础

Hexo 是基于 Node.js 的静态博客框架，由中国台湾的开发者创建，中文文档完善。它把 Markdown 渲染成静态 HTML，再推送到 GitHub Pages 托管。

5. 源码与站点分仓管理

hexo deploy 推送的只是生成后的 HTML。Markdown 源文件、配置和主题需要另外备份，否则换一台电脑就无法继续写作。本站的做法是两个仓库：

仓库 内容 推送方式
用户名.github.io 生成的静态网页 hexo deploy 自动推送
源码仓库（如 blog） source/、_config*.yml、themes/、package.json 等 手动 git push

换电脑时，克隆源码仓库后执行 npm install 即可恢复写作环境。源码仓库的 .gitignore 至少应包含：

**如果站点目录里还放了个人资料、工作文档等非公开文件，一定要把这些目录也加进 .gitignore**。源码仓库通常是公开的，一次 git add . 就可能把它们推上去。

6. 问题记录：真实踩过的坑

6.1 数学公式渲染出错

本站开启了 MathJax 3。有两个容易忽略的细节：

  1. MathJax 3 默认**只识别 $$…$$ 和 \(…\)**，不识别单个 $…$ 的行内公式；
  2. 默认的 hexo-renderer-marked 会把公式里的 _ 当成斜体标记，并吞掉反斜杠。

可靠的写法是把块公式包在 HTML 块里，让 marked 原样透传：

<div> 内部不要留空行，否则 HTML 块会提前结束。

6.2 图片外链大面积失效

从其他平台迁移过来的文章，图片常常是外链。很多平台有防盗链，或者会清理旧图片，一旦失效就是整篇裂图。另一类问题是 Typora 等编辑器默认插入本机绝对路径（如 C:\Users\...\image.png），本地预览正常，上线后必然裂图。

做法：把图片统一下载到 source/images/posts/<文章短名>/，在文章中用 /images/posts/... 的绝对路径引用，并给每张图写有意义的 alt 文字。

6.3 package.json 被覆盖，hexo 命令失效

在站点目录里执行 npm install 某个包，如果当时的 package.json 已损坏或缺失，npm 可能生成一个只含这个包的新 package.json。Hexo 的命令行是靠 package.json 中的 "hexo" 字段识别站点目录的，字段一丢，hexo generate、hexo server 等站点命令就无法使用；换一台电脑 npm install 时，所有 Hexo 插件也都不会被安装。

做法：把 package.json 纳入源码仓库管理，出问题时从 git 历史中恢复，再把新增的依赖合并回去。

6.4 本地正常、线上封面 404

Windows 的文件系统不区分大小写，GitHub Pages 区分。front-matter 里写 bing471.jpg，实际文件名是 Bing471.jpg，本地预览一切正常，上线后封面就是 404。

做法：引用文件时严格按实际文件名的大小写书写，或者统一使用小写文件名。
